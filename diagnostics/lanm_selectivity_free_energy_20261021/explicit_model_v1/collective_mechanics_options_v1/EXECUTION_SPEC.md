# Thin execution contract for the prepared trimer panel

This adds execution plumbing only to the frozen `TRIMER_DECLARATION.md` and preparation manifest. Exactly16 reference cells and16 model cells remain fixed; no new observable, geometry, parameter or threshold is introduced. Original68/78 executors and results remain unchanged.

Reference mode executes one named manifest cell per four-MPI-rank allocation. The root release binds the full16 IDs and a common immutable execution root. Admission is serialized briefly across jobs: a cell directory can be claimed once, and a recorded failure prevents further claims. Already admitted sibling calls can finish and retain their actual outcomes. Each cell permits one native invocation, so the complete inventory permits at most16. Native/parser failures persist and never cause an automatic rerun. Actual allocation memory sets MaxCore; the existing deck and parser enforce the original recipe/state/basis inventories. Raw output, errors and ORCA property files are retained.

Model mode runs the prepared16 rows in a four-CPU allocation, at most four single-thread workers. Exactly one `analyze system.xyz EM` is allowed per row, with an aggregate hard cap16 and immediate global stop on failure. All16 statuses remain visible. Existing native invocation, energy/moment parsing, announced induced-file readback and induction threshold are reused. `.uind`/native type labels use the qualified versioned reader. Existing monomer/dimer/ion results are reused later by the collector; the executor never reruns them.

Root release binds source/config/manifest/preparation and independent preparation/execution reviews, all IDs, finite ceilings, resources and exact output roots. It explicitly excludes fitting, fields, new force/FD work and automatic extension. The source provides read-only `admit_reference` and `admit_model` for collection; these recheck executed inputs and replay raw parsing, with zero new native calls. No summary cycle is computed until the separate collector admits all required new/reused terms.

Per-program wall time is measured. Parallel model child CPU deltas from the inherited helper overlap and are not summed as independent utilization; aggregate process/child CPU and scheduler accounting remain separate. References record allocated elapsed×ranks as a proxy, not measured CPU utilization. No runtime claim is inferred from preparation.

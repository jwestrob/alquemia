# Explicit recovered-slot paired pool and saved comparison bridge

The four ordered slots remain 7CCO/La, 7CCO/Dy, 7CCN/La and 7CCN/Dy. The first,
second and fourth use the unchanged original response protocol and saved-search
admission. Only 7CCN/La may use the separately pinned single embedded-component
recovery protocol, through its explicit `admit_recovered_search` function.
Unknown protocols, the original failed 13019 search, unavailable endpoints and
unbound future results cannot substitute for that admitted recovered slot.

`PAIRED_POOL.py` delegates complete 104-cell parent preparation to the frozen
RESPONSE.py using the original scientific config. It exposes the same
`prepare` and `saved_search` interfaces, with the explicit protocol dispatcher.
The original `paired_pool` function's exact code object runs with a private
copy of its globals containing only that dispatcher substitution. No historical
source, imported module globals, energy method, guard, selection function or
optimizer is modified. Both original and new implementation pins are checked.

All four execution and physical admissions are required before any new paired
score. Preserve all 26 inherited geometries and source-local menus; append at
most four exact-coordinate-deduplicated admitted terminals. Import every
compatible complete search trial through the respective saved reader. Retain
failed requests and their explicit recovery certificate. No unknown failed
request can be retried. The original paired-pool code permits at most four new
opposite-metal composites and stops on a further backend failure. Every new
cell uses the original evaluator/SCC solver; this module supplies no fallback.
Both sources and both metals remain required, with unavailable menus retained.

`PAIRED_POOL.py --stage preflight|pool --config CONFIG --output FRESH` requires
Slurm. Preflight performs the same four saved admissions without scoring. Pool
uses the original all-four gate before any call and requires an allocated GPU.
An unbound recovered-result pin produces `unbound`, not a partial pool. There
is no optimization or new geometry. Root owns launches.

`COMPARE.py` is a separate new-protocol saved-data bridge to the frozen
hybrid_response_comparison/COMPARE.py. Its exact comparison function runs in a
private globals copy with only its own source/protocol and the explicitly pinned
new response-pool dependency. Original replay, finite denominator, native energy
differences, selections, decomposition and interpretation are unchanged. The
pool's public preparation/admission interface verifies the one recovered slot.
The bridge separately reports the preserved failed search, four-call SCC
certification, one-term completion and continuation costs. Completion and
continuation are a breakdown of the recovery allocation, not extra costs to add
twice. Unknown protocols and incomplete parents fail closed. Both original and
versioned scientific identities remain visible; the new results are never
presented as the old response protocol.

The saved comparison still requires the complete 104-cell parent, all four
response slots, the complete final paired pool, fixed Mex common7 and the exact
Module 2 baseline. It performs zero molecular calls. The source-conditioned
four-stage conditional exchange accounting and all nonconvergence limitations
remain unchanged. This bridge introduces no numerical gate or favorable-sign
criterion.

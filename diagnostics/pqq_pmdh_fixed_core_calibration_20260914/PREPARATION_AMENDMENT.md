# Pre-energy preparation amendment: standard-residue-only protonation

**Date:** 2026-09-14  
**Protocol:** `pqq_vertical_swap_r2scan3c_native_cpcm_fixed_core_v3`  
**Status:** implementation correction before any v3 carve or electronic energy

## Observed failure

The first preparation attempt stopped on panel member 1 during protonation,
after CIF normalization but before carving. PDBFixer 1.12.0 calls its private
`_downloadNonstandardDefinitions()` method for every nonstandard residue.
That method attempted to parse the downloaded PQQ CCD definition and failed on
placeholder `?` coordinate values. No fixed-core QM coordinates, ORCA inputs,
or v3 energies were produced.

## Narrow correction

Preparation now invokes the experiment-local `protonate_standard_only.py`
wrapper around the unchanged, hash-pinned `scripts/protonate_cif.py`. During
that one canonical protonation call, the wrapper temporarily replaces the
`pdbfixer.PDBFixer` module symbol with a local subclass. The only altered
chemical behavior is `_downloadNonstandardDefinitions()`—it loads OpenMM's
standard hydrogen definitions and returns an empty mapping. The subclass also
forces the OpenMM CPU platform and asserts the unchanged `forcefield=None`
path. The original module symbol is restored in a `finally` block.

Before applying the wrapper, preparation must verify that the normalized input
contains only the 20 standard amino acids, exactly one PQQ, and exactly one La
residue. PQQ must contain no source hydrogen. Thus the suppressed CCD branch
could only have acted on PQQ or La:

- standard protein residues are still protonated at pH 7.0 by OpenMM's
  unchanged standard definitions;
- PQQ and La are copied without nonstandard hydrogens;
- all three PQQ hydrogens remain exclusively generated by the pinned
  `pqq_ox_3minus_v1` specification during carving; and
- the existing whole-structure heavy-atom identity and coordinate comparison
  still fails on any missing, added, or moved heavy atom.

Hydrogen placement in forcefield-free `Modeller.addHydrogens()` uses Python's
`random` module. The new protonation subprotocol
`pdbfixer_standard_only_rng20260914_openmm_cpu_threads1_v1` therefore seeds it
with `20260914`, forces the OpenMM CPU platform with `Threads=1`, explicitly
requires `forcefield=None`, and restores both the caller's random state and the
CPU platform's previous thread default afterward. The output is required to
contain zero PQQ hydrogens and zero La hydrogens.

The augmented protonation manifest records the canonical protonator, wrapper
hash, suppressed private method, observed nonstandard residue counts, and the
PQQ/La hydrogen policy.

## Protocol disposition

This is a compatibility correction to prevent an undeclared and scientifically
unwanted nonstandard-ligand protonation branch. It does not change the frozen
QM atoms, charges, microstates, coordinates, electronic model, score, or
calibration rule. The protocol ID therefore remains unchanged.

The failed partial attempt is preserved at
`/groups/banfield/projects/environmental/sr/srvp2020/Jacob/lanthanide_binding/on_density_scanner/alchemical_bvs/diagnostics/pqq_pmdh_fixed_core_calibration_20260914/preparation_failed_pdbfixer_ccd_20260914T034403Z/`.
It is not a valid preparation and must not be reused. The default `prepared/`
path is clear for a fresh run after the corrected implementation and hashes
are committed. This amendment authorizes no preparation run or ORCA
calculation by itself.

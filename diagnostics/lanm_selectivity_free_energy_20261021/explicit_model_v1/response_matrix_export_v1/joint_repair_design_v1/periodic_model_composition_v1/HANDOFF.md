# BIO composition adapter handoff

`COMPOSE.py` is source-ready. `CONFIG_UNBOUND.json` leaves the candidate's result/configuration/selected-vector/actual-review pins, adapter source review and engine binding unset. `MANIFEST_TEMPLATE.json` is only a schema example; no actual candidate composition exists.

## Gates before future input preparation

1. Root supplies a source-review receipt with `status: passed_periodic_model_composition_source_review`, exact `implementation` and `inputs` pins.
2. Bind the four candidate pins. The terminal component-campaign result must be complete, mode run, error-free and frozen. Its driver/adapter/core, parent evaluator/configuration, configuration fingerprint, selected index/hash and selected vector must all match. The actual review must have status `passed_component_fit_actual_review`, exact result/configuration/selected joins and `selected_native_admission_passed: true`.
3. Retain the exact declared 12-variable domain. Translate u/v into physical c/d with the original ln4 formula and preserve the domain's fixed native POLPAIR. No older17605 coefficient, live parameter vector or free-form coefficient override is accepted.
4. Verify exact saved box/key/BIO parameter pins, mapped namespace and metal/water/salt roles. Reject occupied900/901, incorrect O/H class roles, missing/duplicate/reversed-duplicate pair records, donor/salt overrides and pre-existing response or field keywords.

After those joins, the root-owned command is:

```text
python3 COMPOSE.py --config <root-bound-config.json> --out <new-nonexistent-output-directory>
```

It creates separate files for both exact boxes: unchanged `system.xyz` and `amoebabio09.prm`, a six-line `metal_water.overlay.key`, a complete `system.prepared.key`, and one pinned manifest. The complete prepared key replaces the four old pair lines and adds two response lines. The six-line overlay is an audit artifact; do not append it to the old mapped key, which would duplicate pair definitions.

The resulting manifest always says `prepared_only_not_executable`. BIO nonmetal/intramolecular/salt records and all nonpair base-key lines remain unchanged. Metal masses stay138.91 Da, with the Dy source162.5 difference explicit as a future dynamics decision. No periodic policy or engine support is inferred.

## Separate future executable binding

`validate_engine_binding(binding, composition_pin)` is a pure prospective gate, with no execution path. It requires pinned engine source/executable/result/review, exact composition identity, affirmative periodic/BIO/dual-field/conservative-force/salt capabilities, numerical checks and explicit PME/image/stability definitions. Its review status contract is `passed_periodic_BIO_response_static_composition_review`. The current vacuum-only engine fails these requirements. This gate does not change the prepared manifest into an executable artifact or authorize a molecular call; future execution requires its own reviewed root integration.

## Source controls

35 small synthetic checks passed in0.041 wall/0.038 CPU seconds on one thread. They exercise physical parameter mapping, domain/order rejection, full-library namespace roles, exact nonpair-line preservation, six translated records, duplicate/missing/salt/donor rejection, terminal/configuration/selection/native-admission joins and absent/unsupported engine capabilities. Synthetic mock receipts are explicitly isolated from real artifacts. The checks do not invoke `prepare`, read any fit outcome, generate actual candidate files, run an engine or select coefficients.

No physical accuracy claim follows from preparing a selected numerical candidate.

## Separate engine binding

Input preparation is allowed without an engine. It never marks output runnable. A separate pure `validate_engine_binding` interface rejects null/unsupported capability receipts. Its prospective contract requires exact composition-manifest, engine-source and executable pins, a passed numerical capability review/result, and affirmative support for translated900/901–402/H403 response, periodic PME, both direct polarization fields, conservative Cartesian/frame forces, original BIO nonmetal terms, and self-consistent Na405/Cl414 polarization/native mixing. It also requires explicit periodic settings and a declared image/stability convention. The current vacuum-only engine does not satisfy this contract. This adapter has no native invocation entry point; future execution remains a separately reviewed root task.

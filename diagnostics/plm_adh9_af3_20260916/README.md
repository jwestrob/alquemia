## Interface

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
 /groups/banfield/users/jwestrob/conda_envs/lanm_qmmm/bin/python \
 diagnostics/plm_adh9_af3_20260916/prepare_af3.py \
 --selected-models /absolute/path/to/selected_models.json \
 --agreement /absolute/path/to/af3_comparison/authorization.json \
 --implementation-pins diagnostics/plm_adh9_af3_20260916/implementation_pins.json \
 --output workspaces/plm_adh9_af3_20260916/preparation
```

The input must contain `cases`, exactly one per approved target. Each has
`target_id`, `case_id`, `rank`, `sample`, `status` (`selected` or `unsupported`),
and a reason when unsupported. Selected cases additionally provide hash-linked
`source_cif` and native `summary_confidences`, `confidence_chain_order`
`["A","B","C"]`, protein chain A, exact La-B/PQQ-C selectors, and the
original explicit core-role dictionaries. Optional `source_provenance` records
are verified and carried into the candidate manifest.

The output `prepared_pairs.json` uses the existing
`plm.adh9.prepared_pairs.v1` execution interface and retains both approved
targets, including unsupported cases and their reasons. Ready carve manifests
live under `pairs/<case_id>/`. Exact raw AF3 source and confidence records are
retained in the handoff. The selector's full all-sample confidence report remains
the authority for predictions that were not selected; this bridge does not
delete, modify, or replace any raw prediction or confidence file.

## Exact adaptation and provenance

`prepare_af3.py` makes byte-identical copies of the selected native CIF and
summary JSON into `adapter_inputs/<case_id>.cif` and
`adapter_inputs/<case_id>_summary.json`. The second filename satisfies the
existing PLM wrapper's naming contract. **No model coordinate, confidence
value, JSON key or null is altered.** Native AF3 legitimately has null entries
such as an ion's confidence diagonal. These are preserved; the protein–La
matrix entry must be finite. Model chain order must match the declared native
confidence order.

The full protein sequence and residue numbering must exactly match the original
scored monomer. The role selectors must exactly match its frozen review:
E205/N270/D321/D323/K345 or E201/N269/D320/D322/K344, respectively. Additional
review annotations are retained upstream; only their selector fields are passed
to the original wrapper. No residue is rediscovered from a distance search.

The bridge invokes the **unchanged**
`diagnostics/plm_adh9_fixed_core_20260916/prepare_candidates.py` through the
hash-pinned preparation Python. It supplies a new, explicitly recorded AF3
candidate manifest and candidate pins while retaining the original calibration
authority and helper hashes. Existing Protenix pairs, source files, controls,
calibration receipts and production defaults remain untouched.

The inherited preparation enforces confidence≥0.9, typed CN≥7 at 3.1 Å,
≤2 direct N donors, explicit homologous fixed core with its Arg/Lys partner
within 3.5 Å of catalytic Asp, and no qualifying off-core donor. It preserves
complete oxidized PQQ³⁻, fixed source geometry, dry conditions and native
ORCA 6.1.1 r2SCAN-3c/CPCM(water). All source/helper/coordinate hashes, zero-heavy-
repair requirements, charge ledgers and identical La/Ca nonmetal coordinates
remain mandatory. Failure is recorded as unsupported without model replacement.

The released fixed-core supported bands remain unchanged: Ca-supported
`S≤14.857129202922806`, La-supported `S≥23.460061205609236` kcal/mol;
the intervening interval is indeterminate. No energies or classifications are
generated by this preparation bridge.
